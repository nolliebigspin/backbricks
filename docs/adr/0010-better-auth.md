# ADR-0010: Dashboard authentication with Better Auth

- **Status:** accepted
- **Date:** 2026-11-04
- **Related:** ARCHITECTURE §0 #9, §D.1, §E.4, §F.1; AGENTS.md I7; PLAN P0.9a, P1.1

## Context

Site owners and their teams sign in to the dashboard. The platform needs email/password, email verification, password reset, organizations with roles (owner, admin, member) and invitations, stored in our Postgres and self-hostable. A later remote MCP server needs an OAuth provider.

## Decision

**Better Auth with the organization plugin, stored in PostgreSQL through the Drizzle adapter, mounted at `/api/auth/*`.** Its tables are generated by the Better Auth CLI (now the `auth` package) and committed into the one migration history. API keys for websites and agents are our own implementation (P1.4), not Better Auth's.

## Consequences

- Organizations, roles and invitations come built in; the tenant model builds on the `organization` table.
- Session cookies are `HttpOnly`, `Secure`, `SameSite=Lax`; mutating dashboard requests require a CSRF header.
- Later: the Better Auth OAuth provider plugin for remote MCP (C3.2).
- The CLI declares `node >=22.12`; behavior on Bun and with TypeScript 7 is verified in the P0 spike (ADR-0020).

## Alternatives considered

- **Auth.js:** weaker organization/role support, more glue code. Rejected.
- **Keycloak / external IdP:** an extra service to self-host. Rejected.
- **Own implementation:** security-critical code to maintain alone. Rejected.
