## Decisions and deviations

The approved 148 h envelope is unchanged: 129 h tasks + 19 h reserve after P3.7a1 used 6 h of reserve. These are planning estimates, not measured work hours. [P3 task history](https://github.com/nolliebigspin/backbricks/blob/a9fc3188aeca064fcbb87ea63911d0d713fcf362/PLAN.md#phase-p3--uploads-m3--v020--approved-2026-11-15) and the ADRs record the decisions.

- Approved seams: [ADR-0063](../adr/0063-module-resource-routes.md) module-owned routes, [0064](../adr/0064-upload-ownership-and-durable-erasure.md) atomic ownership/deferred deletion, [0065](../adr/0065-subject-file-zip-exports.md) authorized streaming ZIPs.
- Execution choices: [0066](../adr/0066-read-only-public-resource-lookups.md) read-only pre-proof resolution; [0067](../adr/0067-configuration-write-availability.md) historical reads versus current write availability; [0068](../adr/0068-attachment-owner-lifetimes.md) owner expiry/locking; [0069](../adr/0069-erasure-requires-enabled-modules.md) fail-closed erasure with RESTRICT identities.
- Further regressions/decisions: [0070](../adr/0070-private-download-deadlines.md) absolute download deadlines after slow I/O; [0071](../adr/0071-archived-project-maintenance.md) archived maintenance/bounded recovery; [0072](../adr/0072-server-finalized-upload-sessions.md) server-finalized sessions; [0073](../adr/0073-subject-export-bounds-and-settlement.md) export ceilings and identity-free settlement; [0074](../adr/0074-erasure-worker-serialization.md) active payload purge and tombstone fences.

The major security correction is ADR-0072: real Garage evidence showed a raw PUT begun before signature expiry can finish afterward. Public uploads now use a single-part multipart session with server-only finalization. There is still one browser PUT; this does not introduce client multipart uploads/resume. Completed/aborted sessions cannot recreate an object. Provider acceptance must exercise the session contract, not only generic PUT compatibility.

One acceptance attempt was interrupted by a large host clock jump and an unresponsive Docker engine; two suites timed out and a later snapshot assertion failed. After a graceful engine restart, all seven affected cases passed unchanged, and the complete quality check was rerun with idle sleep prevented. A later host/VM drift of 24 minutes was measured and aligned before retrying expiry checks. The audit-purge fixture also reproduced a sub-second skew failure: it now takes its timestamp from the database clock that owns the immutable-audit trigger. Production audit protections are unchanged. Interrupted/skewed results are not counted as passing evidence.

Final packaging acceptance caught the server's undeclared direct `zod` import: root development dependencies had hidden it locally. The server now explicitly declares the existing exact 4.6.7 runtime dependency (MIT); the production-only image passes. A failing Compose regression also showed `SCANNER=clamav` was ignored; all application roles now receive the selected scanner and service-internal address.

New runtime parser dependencies (`file-type` 22.3.0, `@tokenizer/inflate` 0.6.0, `strtok3` 10.8.0: MIT; `saxes` 6.0.0: ISC) remain server-only in Uploads, with commit-body justifications. `fflate` 0.8.3 (MIT) is development-only for independent ZIP validation. The SDK adds no runtime dependency and retains Node ≥20 support. Platform/server dependencies may require newer Node; the actual server runtime is pinned Bun and exercised in the image.

## Limits, risks and handoff

- **Release:** [PR #14](https://github.com/nolliebigspin/backbricks/pull/14) merged. See [milestones](../MILESTONES.md#m3--uploads--v020) for publication status.
- **Coverage is specific:** Garage and real ClamAV/Mailpit locally; SDK Bun, Node 20.20.2, Node 24.22.1 and Chromium. The image was built and executed as linux/amd64 through emulation on this arm64 host. No other S3 provider, native arm64 release image, browser engine or malware product was certified.
- **Operational cleanup requires workers/provider access:** access revokes immediately, but physical deletion may wait for outstanding upload deadlines and retry rounds. Keep the provider and owning modules enabled until settlement; do not drop file identities early. Fresh acceptance databases are cleaned only after their own revoked records settle and scoped objects are confirmed absent.
- **Bounded exports:** per-module metadata export limit 10,000 records, ZIP attachment-plan limit 10,000 files, 8 MiB metadata and 1 GiB ZIP32 archive ceiling; limit breaches fail explicitly. There is no silent “first page” export. The manifest explains files that cannot safely be included.
- **Inherited scope:** production Compose/first-run setup, proxy upload mode, backup/restore and release hardening remain M6. Client multipart/resume, transforms, public galleries, cloud billing/quota UI and Reviews are outside M3. Notification delivery remains scheduled and can take roughly two minutes.

All seven explicitly owned browser-acceptance databases were dropped only after cleanup settled. The earlier five had 13 revoked file records/26 remaining scoped keys; the final two had 6 revoked records/12 keys. Real workers removed every remaining record and HEAD confirmed every recorded key absent, with the provider available through upload deadlines. No shared bucket purge or unrelated database deletion was used.
